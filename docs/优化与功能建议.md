### 关于 `npm start` 崩溃（结论修正）

之前记录的"Electron 31 / Node 20 的 CJS→ESM preparse 缺陷"**结论有误**。真实原因是环境变量：

```powershell
ELECTRON_RUN_AS_NODE = '1'    # ← 元凶
```

该变量会让 `electron.exe` 以**纯 Node 进程**启动，而非 Electron 运行时，于是 `import { app } from 'electron'` 走 Node 的 CJS 加载器并崩溃：

```
TypeError: Cannot read properties of undefined (reading 'exports')
    at cjsPreparseModuleExports (node:internal/modules/esm/translators:379)
```

**对照实验**（同一份代码，只改这一个变量）：

| 条件 | 结果 |
|---|---|
| 带 `ELECTRON_RUN_AS_NODE=1` | ✗ `cjsPreparseModuleExports` 崩溃 |
| 清掉该变量 | ✅ 正常启动，窗口标题 `MoYu`，`[preload] loaded`，写出 `app.log` |

**注意**：该变量在本机**既非 User 级也非 Machine 级**（`[Environment]::GetEnvironmentVariable` 两处均为空），说明它是从**当前 shell 会话的父进程**继承来的——很可能是某个工具或 IDE 注入的。重新开一个干净的终端通常即可。

验证方式：

```powershell
Write-Output $env:ELECTRON_RUN_AS_NODE      # 有输出就是它
Remove-Item Env:\ELECTRON_RUN_AS_NODE       # 本次会话内清掉
npm start
```

这条已补进 [`README.md`](../README.md) 的常见问题。

### 关于后端接口（本轮已默认关闭）

应用原本有 2 个后端端点：`GET /api/MoYu/CheckVersion`（版本检测）与
`POST /api/MoYu/ReportDevice`（匿名设备上报）。

现已由 `defaultSettings.backendEnabled`（默认 `false`）统一关闭，**默认完全不发起后端请求**。

顺带修掉一个当时的隐患：`App.vue` 的启动版本检测在**请求失败时也会**强制跳转更新页
（`setForceUpdateActive(true)` + 伪造 `latestVersion: '9999.9.9'`，兜底文案是加 QQ 群）。
关闭开关后该路径不再触发，断网用户不会被锁在更新页。

**注意**：`window.desktop.checkForUpdate()` 是本地 IPC，不是网络请求，因此版本号显示不受影响。

若要恢复后端能力：把 `backendEnabled` 改为 `true`，或在设置面板打开
「启用后端在线服务」。即使打开，匿名上报仍需用户明确同意隐私协议才会发生。

## 二、已实现但可以做得更好的

### ~~2.1 本地阅读器的设置没有全局默认~~（随阅读器一并移除）

主程序仍保留 `readerFontScale` / `readerTextColor` / `forceReaderFont` /
`forceReaderTextColor` 四项设置——它们作用于 **webview 内的网页**（强制改字号与字色），
与已删除的本地阅读器无关，因此**这些设置项继续有效**。

### 2.2 摸鱼统计已有图表，但缺"离开底部"的洞察

**现状**：`StatsPage` 已实现今日实时计时、最近 7 天柱状图、24 小时热力图、按日可展开明细。这部分做得比文档描述的完整。

**可加**：
- **连续时长 Top N**——最长的单次摸鱼会话（现在只有"次数"，没有"最长"）
- **时间轴视图**——把一天的会话画成甘特条，比数字直观
- **周对比**——本周 vs 上周同时段

**注意**：这属于"锦上添花"。1.x 的数据问题优先级更高。

### 2.3 站点规则系统已有三个 provider，其中一个完全没用上

**依据**：`rules/providers/index.js` 聚合 `site` / `toolbar` / `settings` 三类，但 `MainPage.vue` **只读 `combined.site` 和 `combined.toolbar`，从不读 `combined.settings`**。

`settingsRules.js` 里的 `customSettings` 字段（设计意图：按站点覆盖设置，例如"在知乎自动开启透明模式"）是一条**完整实现但从未接线**的死路径。

**建议**（二选一，别让它继续悬着）：
- **接上**：在 `MainPage` 的 `dom-ready` 或路由切换时读取 `combined.settings`，把 `customSettings` 合并进运行时状态。这是很实用的功能——"某些站点自动无图/自动透明"
- 或**删掉**，减少认知负担

### 2.4 内联 `<webview>` 的按键转发是双通道，可能重复

**依据**：`MainPage.onMounted` 注册 `_forwardKeyHandler`，用 `webview.sendInputEvent` 把宿主按键送进页面；同时 `default.js` 规则又在页面内注入 keydown 监听，命中后通过 `console.log('GLASS_SHORTCUT:')` 回传宿主。

两条通道都指向"让页面内按键生效"：前者是宿主→页面，后者是页面→宿主，**方向相反所以不冲突**。但 `_forwardKeyHandler` 无条件转发**所有**按键（含用户在宿主 UI 里的输入），在输入框打字时也会往 webview 灌一遍。目前靠 `document.activeElement` 未做过滤。

**建议**：转发前判断按键目标是否在 `<webview>` 内（`ev.target.closest('webview')`），或仅在 webview 拥有焦点时转发。

## 三、值得做的功能（按"与产品定位契合度"排序）

MoYu 的核心竞争力是**隐身浏览 + 阅读**。以下功能都服务于此，且不需要账号体系。

### 3.1 标签会话恢复（强烈推荐）

**现状**：`tabs` 数组**完全不持久化**（`useTabManager.js` 无任何 storage 调用）。关掉应用，所有标签页丢失，下次只剩一个空白工作台。

**为什么值得做**：
- 这是浏览器类应用最基本的预期
- 用户摸鱼时通常固定开 2–3 个站（微信读书、B站、知乎），每次重开都要重新输入，摩擦很大
- 实现成本低：`tabs` 已是纯数据（`id/title/url/kind`），序列化即可

**建议做法**：
- 在 `useTabManager` 的增删改处防抖写 `localStorage['moyu_tabs_session']`（只存 `url` + `title` + `activeTabId`）
- 启动时若 `defaultUrl` 为空且存在会话，恢复上次标签
- **隐私开关**：加一个"启动时不恢复标签"，默认关闭——毕竟这软件的用户画像很在意痕迹。可结合已有的"最近访问"清理一起做

**注意**：`local-text` 与 blob URL 类标签无法恢复（依赖内存态），恢复时跳过。

### 3.2 老板键的"伪装"能力（差异化最强）

**现状**：`bossKey` 只是 `toggleMainWindow()`（隐藏/显示）。`docs/优化与功能建议.md` 里提过，未实现。

**建议**：
- **静音**：老板键触发时暂停所有 webview 媒体（`usePauseOnBlur.js` 里**已有现成的 `pauseMediaAndScroll()`**，直接复用即可，成本极低）
- **窗口标题伪装**：`win.setTitle()` + 设置项，让任务栏显示成"WPS 表格"之类
- 进阶的"假 Excel 界面"成本较高，可作为远期

**为什么排这么高**：这是"摸鱼工具"相对普通浏览器的**唯一性卖点**，而静音只需要复用已有函数。

### 3.3 定时自动清理痕迹（隐私闭环）✅ 已实现

**原现状**：历史记录最多 200 条、**永不过期**。

**已实现内容**：

| 能力 | 位置 |
|---|---|
| 设置项「历史记录保留」：永久 / 1 / 3 / 7 / 30 天 | 设置面板 → 隐私与痕迹；`defaultSettings.historyRetentionDays` |
| 启动时自动清理过期记录（可关） | `settings.autoCleanOnStartup`，在 `useDesktopApp.initializeDesktopApp` 中触发 |
| 写入时顺带淘汰过期项 | `useRecentVisits.pushRecentVisit` 内调用 `pruneByRetention` |
| 「立即清理过期记录」按钮 | 设置面板，保留天数为「永久」时禁用 |
| 「清除所有痕迹」按钮（二次确认） | 清空历史记录 + 最近访问 + 自定义推荐站点 |

**安全设计**：

- 主进程 `normalizeSettings` 对 `historyRetentionDays` 做**白名单校验**（只接受 `0/1/3/7/30`），其它输入一律回落到 `0`（永久），避免非法值导致误删全部历史
- `time` 字段缺失或无法解析的条目**保守保留**，不因数据异常误删用户记录
- 保留策略与原有 200 条硬上限叠加：先按天数淘汰，再按条数截断

### 3.4 站点规则的导入/导出 ✅ 已实现

**原现状**：规则系统支持静态文件 + localStorage 用户规则，但没有任何导入/导出 UI。

**已实现内容**：

- 新增页面 [`RulesPage.vue`](../MoYu/src/pages/RulesPage.vue)，入口在个人中心 →「站点规则」（路由 `/profile/rules`）
- **导出**：全部规则一键导出，或单条导出；文件名 `moyu-rules-YYYYMMDD-HHmm.json`
- **导入**：支持选择文件或直接粘贴 JSON；两种冲突策略——默认**跳过**已存在的同 `pattern` 规则，可勾选**覆盖**
- **管理**：列表展示、启用/停用、删除（删除有二次确认）
- 导出格式带 `format: 'moyu-site-rules'` 与 `version: 1` 标识，便于日后兼容
- 导出的规则**剔除 `id`**（id 是本机生成的），导入方重新分配，避免冲突
- 导入时只接受已知字段（`pattern`/`matchType`/`enabled`/`preventBlankTargets`/`removeImages`/`customCss`/`customJs`/`name`/`description`），**不把任意字段写进 localStorage**
- 兼容三种输入：本格式导出文件、裸规则数组、单条规则对象

**为什么先做本地版而非远程市场**：`docs/插件市场设计.md` 规划的远程方案需要后端 + 审核机制，且远程脚本会注入 webview 执行，XSS 面很大。本地文件分享同样能形成"规则互换"的效果，风险低得多。

**注意**：`scripts/vendors/` 下的 `.user.js` 文件仍**不会被自动加载**——`import.meta.glob('./scripts/*.js')` 不递归子目录。若要启用，需移到 `scripts/` 根目录或改为递归 glob。这个可以通过新的导入功能变通：把其中的规则转成 JSON 后导入。

### 3.5 广告拦截（体验提升明显）

**现状**：无。`noImageMode` 只是隐藏图片。

**建议**：在 `did-attach-webview` 里对 guest session 挂 `webRequest.onBeforeRequest`，用一份内置域名黑名单拦截。项目**已经有** `did-attach-webview` 的拦截框架（现在用于挡 `zhihu://` 协议），扩展成本低。

### 3.6 暂缓：electron-updater 自动更新

需签名证书（当前 `mac.identity: null` 表示不签名）。现有的"跳浏览器下载"虽简陋但可用，优先级靠后。
