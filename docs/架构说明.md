## 1. 进程模型

```
main process (electron/main.js, 1165 行)
  ├── BrowserWindow 创建/应用设置/事件绑定
  ├── Tray + 上下文菜单
  ├── globalShortcut（仅 bossKey）
  ├── electron-store（width/height/moyuSessions）
  ├── JSON 文件设置持久化（userData/glass-reader-settings.json + .bak）
  ├── 摸鱼计时（窗口 show/hide/minimize/restore/focus/blur）
  ├── autoHide 光标轮询（250ms setInterval）
  ├── did-attach-webview → 导航协议拦截
  └── app.log 日志写入（2MB 截半）

preload (electron/preload.js ESM + preload.cjs CJS wrapper)
  └── contextBridge.exposeInMainWorld('desktop', {...})

renderer (Vue 3)
  └── window.desktop.* 是唯一的特权通道
```

关键安全配置（`BrowserWindow.webPreferences`）：

```js
contextIsolation: true
nodeIntegration: false
sandbox: false          // ← 为让 contextBridge 注入成功而临时关闭
webviewTag: true
devTools: true
```

窗口本体：`transparent: true`、`hasShadow: false`、`backgroundColor: '#00000000'`、Windows 用 `frame: false`、macOS 用 `titleBarStyle: 'hidden'`。

## 2. 主进程详解

### 2.1 设置规范化（核心防线）

`normalizeSettings(partial)` 是主进程对渲染进程传入值的**白名单式校验**，绝不直接信任：

- 数值 clamp：`transparency` 0–100、`autoScrollSpeed` 5–80、`readerFontScale` 80–160
- 颜色校验：`normalizeColor`（`statusBarColor`）、`normalizeReaderColor`（`readerTextColor`）要求严格 `#rrggbb` 正则，否则回落默认值
- Boolean 强制转换：约 25 个开关字段走 `Boolean(partial.x ?? defaultSettings.x)`
- 字符串强制转换：`defaultUrl`、`bossKey` 及 6 个快捷键字段

`loadSettings()` 读取流程：主文件 → 解析失败则读 `.bak` 并回写主文件 → 都失败则整体重置为 `defaultSettings`（**静默**，无 UI 提示）。读取时会剔除 `nonPersistentKeys` 中的字段。

### 2.2 不持久化的临时字段

```js
nonPersistentKeys = new Set([
  'transparency', 'autoHide', 'transparentBackground', 'hoverHeaderMode',
  'pageTransparentMode', 'forcePageTransparent', 'fullWindowTransparent',
  'clickThroughMode', 'alwaysOnTop', 'autoScrollEnabled',
])
```

每次启动从默认值重置——这是刻意设计（透明度/置顶/穿透属于"本次会话"状态，不该跨重启保留）。

> **修复记录**：`fullWindowTransparent` 曾被遗漏。它是顶栏「背景透明」按钮操作的键，
> 遗漏后不在剔除名单里 → 被写入磁盘 → **重启后仍保留上次的透明状态**。
> 加入名单即可修复。新增「会话级」设置项时，务必同步这里，否则会出现同样的"重启未重置"。

### 2.3 窗口设置应用

`applyWindowSettings(win)` 是唯一的窗口属性写入点：

```js
win.setSkipTaskbar(!showInTaskbar)
win.setAlwaysOnTop(alwaysOnTop, 'screen-saver')
win.setContentProtection(antiScreenshotMode)     // 防截屏
win.setIgnoreMouseEvents(clickThroughMode, { forward: true })
win.setOpacity(clamp(1 - transparency / 100, 0.12, 1))   // 下限 0.12 防窗口"消失"
win.setHasShadow(!disableWindowShadow)
process.platform === 'win32' && win.setBackgroundMaterial(transparentBackground ? 'acrylic' : 'none')
```

注意 **透明度是"双轨"**：主进程的 `setOpacity` 影响整个窗口；渲染进程的 `themeVars` 影响 CSS 变量。两者叠加。

### 2.4 autoHide 状态机

用 `setInterval(..., 250)` 轮询 `screen.getCursorScreenPoint()`，有两个独立标志位：

- `bossKeyHidden`：老板键主动隐藏 → 即使 `autoHide: 'hover'` 也不自动恢复
- `autoHideAwaitingEnter`：老板键恢复后（且 `autoHide !== 'hover'`）等待鼠标进入窗口，期间 `blur` 不触发隐藏

`autoHide` 取值语义：

| 值 | 行为 |
|---|---|
| `false` | 关闭 |
| `'hover'` | 鼠标移出隐藏，移回**自动显示** |
| `'hide'` | 鼠标移出隐藏，移回**不显示**（需老板键恢复） |

鼠标移出判定带 12px 容差（`isPointInsideBounds(cursorPoint, trackedBounds, 12)`），避免边界抖动。窗口隐藏后仅在 `hover` 模式下检查光标是否回到窗口区域（6px 容差）。

### 2.5 摸鱼计时

```
show / restore / focus   → startMoyu()
hide / minimize          → endMoyu()
blur                     → 先问渲染进程 window.__moyuShouldKeepTracking()
```

`endMoyu()` **延迟 5 秒**才真正结算（`endMoyuNow`），避免快速切窗口导致会话碎片；且会话短于 **2000ms** 直接丢弃（`if (now - moyuStart < 2000) return`）。

`blur` 时会 `executeJavaScript('!!(window.__moyuShouldKeepTracking && window.__moyuShouldKeepTracking())')`，渲染进程据此在「自动滚动开启」或「有媒体在播放」时返回 true，从而维持计时。

落盘结构：`electron-store` 键 `moyuSessions` = `{ "YYYY-MM-DD": [{ start, end }, ...] }`。

### 2.6 webview 导航拦截

`did-attach-webview` 中对每个 guest `WebContents`（用 `WeakSet` 去重）注册四道拦截：

1. `will-navigate` — 主框架导航
2. `will-redirect` — 服务端 301/302
3. `will-frame-navigate` — 含 iframe（Electron 22+）
4. `setWindowOpenHandler` — `window.open`

统一由 `isBlockedNavUrl(url)` 判定：

```js
if (!/^(https?:|file:|data:|blob:)/i.test(url)) return true   // 自定义协议一律拦截
if (/zhihu\.com\/oia\//i.test(url)) return true               // 知乎 OpenInApp 中转页
```

**这是为知乎专门打的补丁**：`zhihu://` 协议会弹系统对话框，`/oia/` 中转页会白屏。

### 2.7 Tray

图标路径硬编码取自 `defaultSettings.trayIconPath`（`public/icon.ico`），**不读取用户上传路径**。`resolveResourcePath` 依次尝试：绝对路径 → 开发目录 → `app.asar` → `resourcesPath` → exe 同级 `resources/`。macOS 会 resize 到 16×16 并 `setTemplateImage(true)`。

菜单顺序与设置面板保持一致（左列开关 → `toolbarDisabled` → 右列开关 → 速度/字号子菜单）。

### 2.8 日志

`writeLog(level, msg, data)` 追加到 `userData/app.log`。超过 2MB 时读入全文、从**中点后的第一个换行符**处截断保留后半（避免拆开多字节字符）。渲染进程通过 `renderer:log` 通道写入，`logError` 加 `[ERROR]` 前缀。

### 2.9 音频静音（老板键）

`setAllAudioMuted(muted)` 遍历 `webContents.getAllWebContents()` 并逐个 `setAudioMuted()`——**包含各 webview 的 guest 实例**（它们是独立的 webContents）。

接入点是 `hideMainWindow` / `showMainWindow`，而非仅老板键：

```
hideMainWindow()  → setAllAudioMuted(true)     // 老板键、托盘隐藏、autoHide 共用
showMainWindow()  → setAllAudioMuted(false)    // 恢复显示时还原
```

两者都受 `currentSettings.muteOnBossKey` 门禁。这是**进程级静音**，不修改网页自身 `<video muted>` 状态，因此不会与页面逻辑打架。

> **与渲染进程的媒体处理互不干扰**：老板键静音在**主进程**，只认 `muteOnBossKey`；
> 它**不读** `keepAudioPlayingInBackground`（后者属于失焦暂停那条链路）。
> 即：老板键是紧急隐藏，无论音频策略如何设置都会静音。

### 2.9.1 失焦/隐藏时的媒体处理（渲染进程）

`usePauseOnBlur.js` 监听 `document.visibilitychange`：

```
document.hidden = true   → handleHideEvent()  → pauseMediaAndScroll()
document.hidden = false  → handleShowEvent()  → resumeMediaAndScroll()
```

**幂等保护**：`_pausedByHide` 标志确保连续多次隐藏只注入一次、连续多次显示只恢复一次。

**两个设置项共同决定行为**：

| 设置项 | 默认 | 作用 |
|---|---|---|
| `pauseOnBlurHide` | 开 | 总开关；关闭时 `detachPauseListeners()`，完全不响应 |
| `keepAudioPlayingInBackground` | 开 | 音频是否放行 |

**音频判定**：注入脚本内定义 `__glassIsAudioOnly(el)`：

```js
tag === 'audio'                                    → 音频
tag === 'video' && !videoWidth && !videoHeight && 零尺寸  → 音频（播客站常用 video 载音频）
tag === 'video' && CSS 为 display:none/visibility:hidden/opacity:0 → 音频
```

**暂停时打标记，恢复时按标记还原**——这是关键设计：

```js
// 暂停
if (keepAudio && __glassIsAudioOnly(el)) return;   // 放行的音频不留任何标记
el.__glass_reader_prev_muted = el.muted ? 1 : 0;
el.__glass_reader_was_playing = el.paused ? 0 : 1;
el.__glass_reader_paused_by_us = 1;                // ← 恢复时的唯一凭据
el.pause(); el.muted = true;

// 恢复
if (!el.__glass_reader_paused_by_us) return;       // 放行的音频不会被误动
```

没有这个标记的话，恢复时会对所有 `video, audio` 还原，导致放行的音频被误调 `play()`。

**自动滚动**始终会被停止（不受音频策略影响）。

**运行时改动开关**：`MainPage` watch 了 `keepAudioPlayingInBackground`，改动时调 `reevaluatePauseState()`——先按旧策略恢复，60ms 后按新策略重新暂停，避免新旧标记错位。

**注意**：

- 只监听 `visibilitychange`，**不监听 `blur`**。窗口失焦但仍可见时 `document.hidden === false`，不触发
- 最小化走 `minimize()` 不经过 `hideMainWindow`，**不触发主进程静音**，但 `document.hidden` 会变 true，媒体处理仍生效

### 2.10 退出时清理网页数据

`clearAllWebviewData()` 清理 `session.defaultSession`：

```js
clearStorageData({ storages: ['cookies','filesystem','indexdb','localstorage',
                             'shadercache','websql','serviceworkers','cachestorage'] })
clearCache()
```

**为什么需要 `preventDefault`**：`will-quit` 是同步事件，而清理是异步的。若不拦截，进程会在 Promise 完成前退出，清理白做。实现：

```js
app.on('will-quit', (event) => {
  if (currentSettings.clearCacheOnExit && !_privacyCleanupDone) {
    _privacyCleanupDone = true
    event.preventDefault()                     // 先拦住退出
    clearAllWebviewData().finally(() => {
      endMoyuNow(); stopAutoHideMonitor(); globalShortcut.unregisterAll()
      app.quit()                               // 清理完再退
    })
    return
  }
  // 未开启：走原本的同步收尾
})
```

`_privacyCleanupDone` 用于防止 `app.quit()` 再次触发 `will-quit` 形成死循环。

> webview 未配置 `partition`，全部共用 `defaultSession`，所以清理一次即可覆盖所有标签。

## 3. 预加载与 IPC 契约

`electron/preload.cjs` 是真正的 `webPreferences.preload` 目标——它**不是** ESM，而是一个 CJS 包装：动态 `import()` ESM 版 `preload.js`，失败时降级为内联最小实现（缺 `quitWindow`/`checkForUpdate`/`getDeviceId` 等，属部分降级）。

`window.desktop` 暴露的完整 API：

| 方法 | IPC 通道 | 说明 |
|---|---|---|
| `platform` | — | `process.platform` |
| `minimizeWindow` / `maximizeWindow` / `closeWindow` / `quitWindow` | `window:*` | 窗口控制 |
| `openSettingsWindow` | `window:open-settings` | |
| `getSettings` | `settings:get` | 返回 `currentSettings` |
| `updateSettings(s)` | `settings:update` | 保存 + 重注册快捷键 + 重建托盘 + 广播 |
| `setTransparency(p)` | `settings:set-transparency` | 高频专用通道 |
| `setIgnoreMouseEvents(b)` | `ui:set-ignore-mouse-events` | **不改持久设置** |
| `log` / `logError` | `renderer:log` (send) | |
| `onSettingsChanged(cb)` | 订阅 `settings:changed` | 返回取消订阅函数 |
| `onOpenSettingsRequest(cb)` | 订阅 `ui:open-settings` | 返回取消订阅函数 |
| `openExternal(url)` | `shell:open-external` | 主进程校验仅 http/https |
| `getMoyuStats` / `clearMoyuStats` | `moyu:*` | |
| `checkForUpdate` | `update:check` | |
| `getDeviceId` | `device:get-id` | |

`on*` 系列都返回 unsubscribe 闭包，渲染进程在 `onBeforeUnmount` / `disposeDesktopApp` 中调用。

## 4. 渲染进程：App.vue

**1283 行**，分界：`<script setup>` L2–949、`<template>` L951–1190、`<style scoped>` L1192–1283。

### 4.1 职责

2. 快捷键捕获与匹配

4. 窗口热区/悬停逻辑

### 4.2 模板骨架

```
├─ <TopBar>                         hoverHeaderMode 时外包 mouseenter/leave div

```

### 4.3 快捷键三层

| 层 | 位置 | 键 | 生效条件 |
|---|---|---|---|
| 全局 | 主进程 `globalShortcut` | `bossKey` | 永远 |
| 本地 | `localShortcutHandler`（**capture 阶段**） | 透明度±、穿透、自动滚动开关/加减速 | `document.hasFocus() \|\| _mouseInsideWindow` |
| 页面内 | 注入脚本 → `console-message` → `handleShortcutMessage` | 同上 | 页面获得焦点 |

`bossKey` 在渲染进程被**显式忽略**（`localShortcutHandler` 提前 return），避免与主进程重复触发。

**Accelerator 格式**（`formatAcceleratorFromEvent`）：
- 修饰键顺序固定 `Ctrl → Alt → Meta`
- **Shift 被双重禁止**作修饰符：录制时 `_onCaptureKeydown` 弹警告丢弃；格式化时直接不采集
- 键名映射：`' '→Space`、`Escape→Esc`、`ArrowUp→Up`、`ArrowDown→Down`、`ArrowLeft→Left`、`ArrowRight→Right`
- Shift 符号还原：`'+'→'='`、`'{'→'['`、`'}'→']'`
- 单字符大写，F1–F12 原样

**匹配算法**（`parseAccelString` + `accelEquals`）：按 `+` 切分（`++` 先转义为 `+PLUS`），末段为主键，前缀段构成修饰键 `Set`。要求**主键相同且修饰键集合完全相等**——所以 `Ctrl+Alt+T` 等价于 `Alt+Ctrl+T`，但 `Ctrl+T` 不会误匹配。

**本地快捷键动作表**：

| 设置键（默认值） | 动作 |
|---|---|
| `decreaseTransparencyShortcut` (`Alt+Up`) | `transparency - 8`，下限 0 |
| `increaseTransparencyShortcut` (`Alt+Down`) | `transparency + 8`，上限 85 |
| `clickThroughShortcut` (`Ctrl+Alt+T`) | 切换 `clickThroughMode` |
| `autoToggleShortcut` (`=`) | 切换 `autoScrollEnabled` |
| `autoSpeedDownShortcut` (`[`) | 速度 −5，下限 5（仅开启时） |
| `autoSpeedUpShortcut` (`]`) | 速度 +5，上限 80（仅开启时） |

注意主进程侧托盘/设置允许 `transparency` 到 100，但快捷键上限是 85，`TopBar` 循环档位是 `[0, 20, 50, 85, 100]`。

### 4.4 设置面板

**没有 tab**，单页纵向堆叠：

1. `.settings-header` — "设置中心"
2. `.slider-block` — 透明度 `input[type=range] 0–100` → `handleTransparencyInput`
3. `.toggle-grid` 两列
   - 左「窗口行为」← `leftToggleKeys`（9 项）+ 硬编码的 `toolbarDisabled` 行
   - 右「显示与渲染」← `rightToggleKeys`（11 项）
4. `.shortcut-block` — 7 个 `<ShortcutRow>`
5. 恢复默认（`el-button type="danger"`，两次 `ElMessageBox.confirm` 二次确认）

`restoreDefaults()` 只重置**开关 + 快捷键**，不动 `readerTextColor`、`autoScrollSpeed`、`defaultUrl` 等。

**穿透恢复协议**：`openSettingsModal` 强制 `setIgnoreMouseEvents(false)`；`closeSettingsModal` 重新 `getSettings()` 后按 `clickThroughMode` 回写。这是鼠标穿透下唯一能唤回交互的路径（除快捷键）。托盘「打开设置」也会走 `openSettingsPanel` → 发 `ui:open-settings`。

### 4.5 热区与 header 悬停

`hoverHeaderMode` 开启时：

- 热区高度 `updateHotzoneFromDOM()` = `max(24, 28 + tabbar高 + topbar高 + 8)`，由 `ResizeObserver` 观察 `.header-hotzone` / `.topbar` 驱动
- `pointermove` + `pointerdown`（**rAF 节流**，`_pmRafId` 防重入）→ `_onPointerMoveForHeader`
- `near = e.clientY <= hotzoneHeight`，且 target 在 `.topbar`/`.tabbar` 内也算 near
- **进入立即显示，离开延迟 `HEADER_HIDE_DELAY = 360ms` 隐藏**
- 回退：`mouseout`（`relatedTarget === null` 即真离开窗口 → 立即隐藏）、`mouseover`、`blur`

视觉落在 `style.css` L1490–1589：`.mode-hover-header .topbar/.tabbar` 默认 `opacity:0; pointer-events:none`；`.header-hover-active` 时 `opacity:1; z-index:10000`。

### 4.6 顶栏透明度交互（`TopBar.vue`）

顶栏那个百分比按钮承担三种操作。**没有引入滑块**——顶栏宽度紧张，弹簧式滑块会挤压其它控制组；滚轮微调既精细又不占 DOM 空间。

| 操作 | 实现 | 行为 |
|---|---|---|
| 滚轮 | `@wheel.prevent="onOpacityWheel"` | 每格 **±1%**，范围 0–100 |
| 单击 | `@click="onOpacityClick"` | 循环预设 `0 → 20 → 50 → 85 → 100 → 0` |
| 双击 | `@dblclick="onOpacityDblClick"` | `0` ⇄ 上次非零值 |

**上限为何是 100**：设置面板的滑块是 0–100，而快捷键那套历史上限是 85（`App.vue` / `MainPage.vue` 里 `Math.min(85, ...)`）。两者本就不一致，顶栏取 100 与滑块对齐、更直观。

**双击的"上次非零值"**（`lastNonZeroOpacity`）：在 `setOpacity()` 内，只要当前值 > 0 就更新它。因此滚轮结果会被记住——滚到 13% → 双击归零 → 再双击回到 13%。从未设过非零值时给兜底 50%。

**单击必须延迟执行**（`DBLCLICK_DELAY = 220ms`）——这是本功能最容易踩的坑：

```
双击 = click, click, dblclick 三个事件依次触发
若 click 立即执行循环切换 → 透明度连跳两档，再被 dblclick 归零，观感错乱
```

处理：`onOpacityClick` 首次点击时挂起定时器，等待期内若发生第二次点击就 `clearTimeout` 并让 `dblclick` 接管。

**其他细节**：

- `preventDefault` + `stopPropagation` 防止滚轮穿透到下层页面
- 调节时 `.opacity-adjusting` 让数字 `scale(1.18)` 闪 420ms，作为生效反馈
- 指针为 `cursor: ns-resize`，提示"可上下滚动调节"
- `onUnmounted` 同时清理 `_clickTimer` 与 `_adjustTimer`

### 4.7 顶栏与右下角的职责划分

两个快捷区**刻意不重叠**，按「作用域」分工：

| 区域 | 作用域 | 内容 |
|---|---|---|
| **顶栏** `TopBar.vue` | **窗口级 + 外观** | 透明度、背景透明（三态）、悬停标题栏、自动隐藏、置顶、设置、关闭 |
| **右下角** `BottomToolbar.vue` | **页面级 + 阅读** | 后退/前进/刷新、缩放、字号、字色、无图、滚动条、自动滚动、外部打开 |

加新按钮时按这个边界决定放哪：**改变窗口外观 → 顶栏；改变网页内容 → 右下角**。
（导航与缩放虽然在语义上属"浏览"，但右下角已有完整一组，保持聚集。）

### 4.8 背景透明的三态按钮

原先顶栏有**两个**独立按钮（`fullWindowTransparent` 与 `pageTransparentMode`），
两者只差「网页是否也透明」，用户难以区分却占两个位置。现合并为一个三态循环，
**顺序为「软件优先」**：

| 档位 | 状态 | `shellOnlyTransparent` | `pageTransparentMode` | `fullWindowTransparent` | 图标 |
|---|---|---|---|---|---|
| 0 | 关闭 | false | false | false | `Monitor` |
| 1 | 软件透明 | **true** | false | false | `Moon` |
| 2 | 软件+网页都透明 | false | **true** | **true** | `View` |

**实测三档的 CSS 变量值**（transparency = 0）：

| 档位 | `--shell-alpha` | `--surface-alpha` | `--page-alpha` |
|---|---|---|---|
| 0 关闭 | 1 | 1 | 1 |
| 1 软件透明 | **0** | **0** | **1** |
| 2 软件+网页 | **0** | **0** | **0** |

三个变量分别控制（见 `src/style.css`）：

- `--shell-alpha` → **外壳**（窗口外框、标题栏）
- `--surface-alpha` → **面板**（工具栏、浮动面板）
- `--page-alpha` → **网页区域**

#### 为什么必须新增 `shellOnlyTransparent`

**旧的两个键组合不出「只软件透明」这一档**：

- 只开 `pageTransparentMode` → `shellAlpha` 走 `Math.max(0.70, 0.98 - t/130)`，
  **最小值 0.70**，永远到不了 0；而且网页也会跟着变透明
- 只开 `fullWindowTransparent` → 三个 alpha 全部归零，网页**也**透明了

所以档 1 需要独立的键与独立的 `themeVars` 分支：

```js
if (settings.fullWindowTransparent) { /* 全部 0，优先级最高 */ }
if (settings.shellOnlyTransparent) {
  return { '--shell-alpha': '0', '--surface-alpha': '0', '--page-alpha': '1', ... }
}
```

**分支顺序不能颠倒**：`fullWindowTransparent` 在前，它优先级更高。

#### 状态的清除关系

进入档 2 时会清掉 `shellOnlyTransparent`——它的效果被 `fullWindowTransparent`
完全覆盖，留着只会让状态产生歧义。`useSettings` 里还确保档 1 不会连带开启
`forcePageTransparent`，否则「网页保持不透明」的语义会被破坏：

```js
if (key === 'shellOnlyTransparent' && settings[key]) settings.forcePageTransparent = false
```

`contextMenuItems` 的背景透明子菜单与顶栏三档**语义完全一致**（相同的三个键组合）。

各读取点均用「任一即真」，多键同开无冲突：

```js
settings.pageTransparentMode || settings.fullWindowTransparent   // useWebviewSync / ConsolePage / HomePage
```

### 4.9 图标语义与状态标记

原先激活态**只靠变蓝**（`.ctrl-btn.active`），小窗口下图标本身语义模糊。改进：

| 按钮 | 原图标 | 现图标 | 原因 |
|---|---|---|---|
| 悬停标题栏 | `Hide` | `Hide` ⇄ `View` | `Hide` 易与「隐藏窗口」混淆；开启后换成「眼睛」表示"看得见" |
| 自动隐藏 | `Pointer` | `Top` | `Pointer` 看不出"鼠标移出才隐藏"；`Top` 暗示移出顶部区域 |

所有开关类按钮在激活时额外加**右下角状态点**（`.state-dot`）——4px 蓝点 + 白色描边。
三态的最高档用**双点**（拉宽的胶囊）区分。

### 4.10 响应式（修正）

**原先的写法是死代码**：用 `flex: 0 3 auto` / `flex: 0 2 auto` 期望按钮被压缩消失，
但 `.ctrl-btn` 有 `min-width: 22px !important`，**按钮无法压缩到 0**——
flex 收缩不会让按钮消失，只会让 `overflow: hidden` 从右侧把它切掉。

实测（逐档改窗口宽度）：**即使窄到 360px，8 个按钮仍全部完整可见**，控制区固定占 232px。
也就是说这套机制从未被触发过，真正生效的是「放得下」。

现改为**媒体查询整组隐藏**，阈值基于实测余量：

```css
@media (max-width: 420px) { .grp-collapsible-a { display: none } }  /* 透明度组 */
@media (max-width: 340px) { .grp-collapsible-b { display: none } }  /* 可见性组 */
/* .grp-essential（设置/最小化/关闭）永不隐藏 */
```

### 4.11 生命周期

`onMounted`：`initializeDesktopApp()` → 条件 `reportDevice()` → 注册 `window.__moyuShouldKeepTracking` → 各种事件绑定 → 版本检查 → 订阅 `ui:open-settings` → `localShortcutHandler`（capture）→ `error`/`unhandledrejection` 全局捕获。

`onBeforeUnmount`：逐项对称清理 + `disposeDesktopApp()`。

**无 `watch`、无 `onUpdated`。**

## 5. 渲染进程：MainPage 与 webview

### 5.1 渲染方式

```html
<webview
  v-for="tab in pageTabs"                              <!-- kind === 'page' -->
  v-show="String(tab.id) === String(activeTabId)"      <!-- 显隐，不是卸载 -->
  :key="tab.id"
  :data-tab-id="tab.id"
  :ref="getWebviewRefSetter(tab.id)"
  :src="tab.url"
  :useragent="userAgent"
  nodeintegration="false"
  enableblinkfeatures="ResizeObserver"
  @dom-ready="handleWebviewDomReady"
  allowpopups />
```

- `pageTabs` 只含 `kind === 'page'`；dashboard 走 `v-if` 的 overlay 层
- **未使用 `partition`** → 所有 webview 共享默认 session（cookie/localStorage 互通）
- **未使用 `preload`** → webview 内没有特权 API，只能靠 `executeJavaScript` + `console-message` 通信
- `v-show` 意味着所有 page 标签的 webview **常驻内存**，切回不重载（代价是内存随标签数线性增长）

### 5.2 切换标签时的动作序列

`watch(activeTabId)` → `stopLocalReaderAutoScroll()` → `syncLocalReaderAutoScroll()` → 清除 `__glassReaderAutoScrollPaused` → 更新 `webviewReady` → `await nextTick()` → `syncReaderEffects(newId)` → `updateEffectiveToolbar()`

### 5.3 dom-ready 处理流水线

`handleWebviewDomReady(e)`：

1. **1200ms 去抖**（`webviewDomReadyTs`），防止重复触发
2. `setWebviewRef(w, tabId)` + `webviewReadyMap[tabId] = true`
3. 同步全部 reader 效果（透明/无图/滚动条/文字色/字号/自动滚动）
4. 注入媒体监听（guard `window.__glassReaderMediaMonitor`），监听 `play/pause/ended/loadeddata`，通过 `chrome.ipcRenderer.sendToHost('media-status', {playing})` 上报
5. `mobileMode` 时注入 viewport meta
6. 同步 `siteZoom`
7. 规则匹配与注入

第 4 步的 `sendToHost` 对应 `useWebviewRefs` 的 `ipc-message` 监听，最终在 webview 元素上写 `data-media-playing="1"`，供 `App.vue` 的 `__moyuShouldKeepTracking` 与 CSS 读取。

### 5.4 webview 事件监听清单

绑定于 `setWebviewRef(el, id)`（替换实例时先解绑旧的，`el === null` 时全量清理）：

| 事件 | 行为 |
|---|---|
| `did-finish-load` | 仅 log |
| `did-navigate` / `did-navigate-in-page` | `recordNavigation` → 记历史 |
| `did-fail-load` | 仅 `console.warn` |
| `console-message` | 转发为 `[webview.console]`；`GLASS_SHORTCUT:` 前缀转 `handleShortcutMessage` |
| `ipc-message` | `media-status` → 写 `data-media-playing` |

**未监听**：`page-title-updated`、`new-window`、`did-start-loading`、`did-stop-loading`。

`recordNavigation` 的过滤：跳过 dashboard 标签、跳过 `about:` 前缀、用 `webviewLastRecordedUrl[tid]` 对同一 URL 去重；标题通过 `executeJavaScript('document.title || ""')` 异步获取，失败回落为 URL。

### 5.5 页面内快捷键回传链路

```
default.js 注入 keydown 监听
   → 命中则 console.log('GLASS_SHORTCUT:{"action":"..."}')
   → webview console-message 事件
   → _shortcutHandler (MainPage.handleShortcutMessage)
   → patchSetting(...)
```

另有反向通道：`_forwardKeyHandler`（capture `keydown`/`keyup`）用 `webview.sendInputEvent({ type, keyCode, modifiers })` 把宿主按键送进 webview。注意 `keyCode` 直接传 `ev.key`（字符串），这是 Electron 的宽松用法。

### 5.6 webview 内右键菜单

**为什么必须走主进程**：`<webview>` 的 guest 是独立 `webContents`。渲染进程在 `<webview>` 元素上**收不到** `contextmenu` DOM 事件（这不是宿主文档里的事件），唯一可靠入口是主进程的 `wc.on('context-menu')`。

```
guest 内右键
 └→ 主进程（在 did-attach-webview 里注册）
      wc.on('context-menu', (ctxEvent, params) => {
        ctxEvent.preventDefault()                 // 挡掉 Chromium 默认英文菜单
        mainWindow.webContents.send('contextmenu:show', {
          x, y, isEditable, linkURL, selectionText, mediaType, pageURL,
        })
      })
           ↓ IPC
      渲染进程 preload: window.desktop.onContextMenu(cb)
           ↓
      MainPage.handleContextMenuFromMain(payload)
        ├─ toWindowCoords()  ← 坐标换算
        └─ ctxMenu = { visible: true, x, y }
             ↓
      <ContextMenu> 渲染 → 点击 → onContextMenuItem → 执行 action
```

**坐标换算（易错点）**：`params.x/y` 相对 **guest 页面内容区**，而菜单要显示在**宿主窗口**坐标系里。`toWindowCoords()` 叠加 webview 元素的 `getBoundingClientRect()`：

```js
x = webviewRect.left + params.x
y = webviewRect.top  + params.y
```

取不到 webview 时回退为原坐标（宁可位置偏一点也不崩）。

**菜单结构**（`MainPage.contextMenuItems` 是一个 `computed`，依赖 `activeTab` / `settings`）：

| 区块 | 项 | 禁用条件 |
|---|---|---|
| 背景与外观 | 背景透明 ▸（三档）、窗口透明度 ▸（5 档）、灰度模式 | 始终可用 |
| 站点 | 将本页加入推荐站点 | 非 `page` / 无 URL / 已在推荐中 |
| 站点工具 | 查看本站生效的规则、打开开发者工具 | 非 `page` 标签 |

取舍说明：

- **只保留右下角工具栏没有的能力**。曾统计 11 项能力中 5 项与右下角重复
  （后退/前进/刷新/无图/缩放），已全部移除，菜单从 9 项降到 6 项
- **保留的都是"站点级"能力**：排查规则命中、开 DevTools、加入推荐站点。
  这类操作天然适合"就地右键"，塞进右下角反而埋深
- **刻意为空**的项：复制选中文字、复制链接、在新标签打开链接、搜索选中内容——需求上已明确不要
- 背景与外观类**不依赖页面内容**，因此在工作台（dashboard）标签下仍可点击；站点类则禁用

> 为什么删了导航项还留右键菜单：右下角工具栏需要「移到热区 → 等 FAB 淡入 → 点击展开」
> **三步**，而右键是**一步**。摸鱼场景下这一步的差别很显著。

**「查看本站生效的规则」**：调用 `ruleProviders.getCombinedRulesForUrl(url)` 取 `combined.site`，把命中的规则名写进 `statusMessage`（顶部栏显示 2.5s）。这是排查「油猴脚本是否真的生效」的快捷入口。

`ContextMenu.vue` 的契约（改动时保持）：

| 字段 | 作用 |
|---|---|
| `children: []` | 渲染为子菜单（父项右侧显示 `›`），点击父项本身不触发 action |
| `type: 'separator'` | 分隔线 |
| `disabled: true` | 灰显且不可点 |
| `hint: string` | 右侧灰色提示（如 `F5`、`85%`、`已开启`） |
| `action: () => void` | 点击后由 `MainPage.onContextMenuItem` 调用 |

实现要点：**子菜单渲染为独立的 `.context-menu.submenu` 层**（不是父级 DOM 的子节点），否则会被父级的 `overflow` 裁掉。主菜单与子菜单都有边缘避让（靠右/靠下时翻转，`EDGE_GAP = 4`）。

#### 自适应尺寸与溢出折叠

摸鱼场景下窗口通常很小，固定尺寸既笨重又容易溢出。`ContextMenu.vue` 因此有两层自适应：

**第一层：按窗口算尺寸令牌**（`computeMetrics()` → CSS 变量 `--cm-font` / `--cm-item-h` / `--cm-pad-y`）

| 窗口条件 | 行高 | 字号 |
|---|---|---|
| `vh < 320` 或 `vw < 380` | 20px | 10.5px |
| `vh < 520` 或 `vw < 560` | 23px | 11px |
| 其它 | 26px | 12px |

（改版前固定 32px 行高 / 13px 字号。）

**第二层：放不下就折叠**（`computeOverflow()` → `overflowItems` → `visibleItems`）

```
1. 估算全部项高度；放得下 → 不折叠
2. 放不下 → 从**尾部往前**折叠（越靠后越次要）
3. keepAlways：头部 KEEP_HEAD = 3 个真实项始终保留
   ↳ 保底意义：窗口极小时不能让菜单只剩一个「更多」入口，那样等于没有菜单
4. 折叠组首尾的 separator 去掉
5. visibleItems = 保留项 + 尾部自动生成的「更多」子菜单
```

实测（itemH = 20 的小窗口档）：

| 可用高度 | 结果 |
|---|---|
| ≥ 140px | 全部 6 项放得下，不折叠 |
| 120px | 折叠 `查看规则` / `开发者工具` |
| ≤ 80px | 只剩 `背景透明` / `窗口透明度` / `灰度模式` + 更多，**所有功能仍可达** |

菜单全高：**140px**（itemH=20）/ **182px**（itemH=26），比删减前的 210px 明显更省。
`window.resize` 时重算——摸鱼窗口常被拉伸。子菜单高度估算同样使用 `metrics.itemH`，不再硬编码。

## 6. 状态层（composables）

```
useAppState.js          共享 ref/reactive + 工具函数（normalizeUrl / getTitleFromUrl / generateUniqueTabId）
    ↑
useSettings.js          patchSetting / toggleSetting，120ms 防抖，immediateSyncKeys 立即同步
useRecentVisits.js      最近访问，localStorage glass_reader_recent_visits，上限 200，2s 防抖
                        另含 pruneByRetention / pruneExpiredVisits（按天保留）
useTabManager.js        标签 CRUD
useRecommendedSites.js  推荐站点（6 个内置 + 用户自定义）
    ↑
useDesktopApp.js        聚合导出 + 计算属性（filteredRecentVisits / shellClasses / themeVars）
                        另含 clearAllTraces / cleanExpiredTraces（隐私清理）
```

### 6.1 `patchSetting` 的三条路径

```js
if (key === 'transparency')      // 特殊：先 setTransparency，300ms 后再全量 updateSettings
else if (key === 'autoScrollSpeed')  // clamp 5–80
else if (key === 'readerFontScale')  // clamp 80–160
else                              // 直接赋值

if (immediateSyncKeys.has(key)) syncSettingsNow()   // 立即
else scheduleSettingsSync()                          // 120ms 防抖
```

`immediateSyncKeys` 几乎涵盖所有开关与全部快捷键。`patchSetting` 还内联了一堆 `statusMessage` 文案（顶部栏会显示 2.5s）。

### 6.2 `themeVars` 透明度的 CSS 计算

```js
fullWindowTransparent              → --shell-alpha/surface/page 全为 '0'，header-tint: transparent
!fullWindowTransparent && !page    → 全部 '1'，纯白背景
否则（pageTransparentMode 或部分透明）→ 按 transparency 线性插值，带下限
```

透明度映射（`transparentBackground` 开启时更陡）：

| 变量 | 关闭 transparentBackground | 开启 |
|---|---|---|
| `shellAlpha` | `max(0.70, 0.98 − t/130)` | `max(0.05, 0.95 − t/90)` |
| `surfaceAlpha` | `max(0.75, 0.97 − t/140)` | `max(0.08, 0.92 − t/95)` |
| `pageAlpha` | `max(0.72, 0.96 − t/145)` | `max(0.04, 0.94 − t/88)` |

### 6.3 `activeTab` 与 `activeTabId` 的不一致

`tabs` 初值 `[{ id: 0, ... }]`，`activeTabId` 初值 `1`。`activeTab` 是 `computed(() => tabs.find(t => t.id === activeTabId) ?? tabs[0])`，靠 `??` 兜底。功能上无碍，但初始化瞬间存在无匹配状态。

### 6.4 隐私清理与会话

设置面板「隐私与痕迹」区块涉及的功能，实现分散在三处：

| 函数 | 位置 | 行为 |
|---|---|---|
| `pruneByRetention(list, days)` | `useRecentVisits.js` | 按天过滤；`days = 0` 表示永久；`time` 缺失/非法的条目**保守保留** |
| `pruneExpiredVisits()` | `useRecentVisits.js` | 立即清理内存 + 落盘，返回移除条数 |
| `cleanExpiredTraces()` | `useDesktopApp.js` | 对外的清理入口，供 UI 调用 |
| `clearAllTraces()` | `useDesktopApp.js` | 清空历史 + 自定义推荐站点 + **标签会话**，返回 `{ cleared: [...] }` |
| `persistSession()` / `flushSession()` | `useTabManager.js` | 会话落盘（800ms 防抖 / 立即） |
| `restoreSession()` | `useTabManager.js` | 启动恢复，返回 `{ restored }` |
| `clearSavedSession()` | `useTabManager.js` | 丢弃已保存会话 |
| `setAllAudioMuted(muted)` | `electron/main.js` | 进程级静音所有 webContents |
| `clearAllWebviewData()` | `electron/main.js` | 清理 defaultSession 的浏览数据 |

`pushRecentVisit` 内会顺带调用 `pruneByRetention`，因此过期条目在写入时即被淘汰。保留策略与原有的 **200 条硬上限**叠加：先按天数淘汰，再按条数截断。

`historyRetentionDays` 在主进程 `normalizeSettings` 中做**白名单校验**（只接受 `0/1/3/7/30`），其它输入一律回落为 `0`，避免非法值误删全部历史。

#### 标签会话的生命周期

```
打开/关闭/切换标签
   └→ persistSession()  ── 800ms 防抖 ──→ localStorage['moyu_tabs_session']
窗口关闭（pagehide / beforeunload）
   └→ flushSession()    ── 立即落盘
应用退出（onBeforeUnmount → disposeDesktopApp）
   └→ flushSession()

下次启动
   └→ desktopApi.getSettings().then(...)
        ├─ Object.assign(settings, ...)      ← 必须先拿到 restoreTabsOnStartup
        └→ restoreSession()
```

**两个容易踩的点**：

1. `restoreSession()` 必须在 `settings` 加载**之后**调用，否则 `restoreTabsOnStartup` 还是默认值，开关形同虚设。
2. `closeToTray` 默认开启时关闭窗口只是 `hide()`，**不触发 `onBeforeUnmount`**——只靠 `disposeDesktopApp` 会漏掉最常见的退出路径，因此额外监听 `pagehide` / `beforeunload`。

## 7. 站点规则注入系统

### 7.1 三类规则 provider

| provider | 来源 | localStorage 键 | 消费点 |
|---|---|---|---|
| `site` | `src/rules/scripts/*.js`（`import.meta.glob` 静态）+ 用户规则 | `glass_reader_site_rules` | `MainPage` dom-ready 注入 |
| `toolbar` | 用户规则 | `glass_reader_toolbar_rules` | `MainPage.updateEffectiveToolbar`、allowNewWindow 判定 |
| `settings` | 用户规则 | `glass_reader_settings_rules` | **未被消费**（死路径） |

`getCombinedRulesForUrl(url)` 返回 `{ site, toolbar, settings }` **三路平级，不做跨 provider 合并或优先级仲裁**。

### 7.1.1 备份/恢复与油猴脚本导入

`rules/index.js` 额外导出：

| 函数 | 作用 |
|---|---|
| `exportRules({ ids })` | 生成备份对象，含 `format: 'moyu-site-rules'` / `version: 1`；**剔除 `id`**（本机生成，导入方重新分配） |
| `importRules(payload, { overwrite })` | 兼容三种输入：备份对象 / 裸数组 / 单条对象；`overwrite` 为假时跳过同 `pattern` 冲突 |
| `validateImportedRule(raw)` | **字段白名单**，只保留已知字段，避免任意字段写进 localStorage |
| `isUserscript(text)` | 检测 `==UserScript==` 元数据块 |
| `parseUserscript(text)` | 解析 `@name/@version/@description/@author/@match/@include/@exclude/@grant/@run-at`，返回 `{ meta, body, globals }` |
| `convertUserscriptPatterns(ps)` | 把 `@match` 降级为本应用的 pattern（见下表） |
| `convertUserscriptToRule(text)` | 完整转换；返回 `{ ok, rule, meta, warned }` |

**`@match` → pattern 的降级规则**（本应用按 hostname 匹配，已支持 `*` 通配符与子域后缀）：

| 油猴写法 | 转换结果 | 说明 |
|---|---|---|
| `*://*.zhihu.com/*` | `zhihu.com` | 去掉 `*.` 与协议；hostname 模式本身匹配子域 |
| `https://www.zhihu.com/question/*` | `www.zhihu.com` | 丢弃路径 |
| `https://host.com:8080/x` | `host.com` | 丢弃端口 |
| `/^https?:\/\/zhuanlan\.zhihu\.com\//` | 原样保留 | 生成 `matchType: 'regex'` |
| `*://*/*` | **跳过** | 会命中所有站点，拒绝以免误伤 |

**matcher 的一处配套修复**：`matchRule.js` 在处理数组 pattern 时，逐项递归会继承父级 `matchType`。这导致数组里混入的 `"/正则/"` 字符串被当成字面 hostname，**永不命中且不报错**。现已在数组分支内检测 `/.../ ` 形式并强制该项按 `regex` 判定。

**已知限制**：不提供 `GM_*` API；`@run-at` 一律按 `dom-ready`；`@exclude` 不生效。导入时会在 UI 上明确提示这些兼容性风险。

### 7.2 规则合并顺序

`site.getRulesForUrl` 的数组顺序为：

```
staticDefaults (default.js，isDefault: true)  →  staticSiteRules (其余静态文件)  →  用户规则
```

`isDefault` 的规则**对所有 URL 无条件生效**，其余走 `matchesRule`。用户规则在数组末尾仅是顺序靠后——**没有"后写覆盖"机制**，所有命中的规则都会被执行。

### 7.3 `matchesRule` 完整判定树

```
rule 或 rawUrl 为空                              → false
typeof rule.match === 'function'                 → !!rule.match(rawUrl)     [最高优先级]
Array.isArray(rule.pattern)                      → 逐项递归，任一命中即 true
rule.pattern instanceof RegExp                   → test(rawUrl) || test(hostname)
pattern 为空                                     → false
matchType = rule.matchType || 'hostname'
  ├─ 'regex'    → new RegExp(pattern).test(raw) || test(hostname)
  ├─ 'url'      → raw.toLowerCase().includes(pattern.toLowerCase())
  └─ hostname（默认）
       ├─ 含 '*' → 按 '*' 切分，各段 escape，用 '.*' 连接，^...$ + i 标志
       └─ 无 '*' → (^|\.)escaped$ + i 标志   ← 精确主机或子域后缀
URL 解析失败 → rawUrl.toLowerCase().includes(pattern.toLowerCase())
```

### 7.4 注入 API 与两种规则形态

**规则有两种形态，`MainPage` 的注入循环必须同时处理**（`handleWebviewDomReady` 内）：

| 形态 | 来源 | 判定 | 注入方式 |
|---|---|---|---|
| **函数型** | 内置 `src/rules/scripts/*.js` | `typeof r.apply === 'function'` | 调用 `r.apply(helper)`，由规则自己决定注入什么 |
| **数据型** | 用户规则 / **油猴导入** | 无 `apply` | 读取 `r.customCss` / `r.customJs` 字段直接注入 |

> ⚠️ **曾经的缺陷**：注入循环最初只有 `if (typeof r.apply === 'function')` 一个分支，
> 而 `rules/index.js` 会把静态模块的 `export default function` 挂成 `apply`——
> 于是**只有内置脚本有效**，所有纯数据型规则（用户手写 + 油猴导入）的 `customCss` / `customJs`
> **从未被读取过**。表现为「导入成功但页面无任何效果」。
>
> 修复：在 `else` 分支中显式注入两个字段，并加 `[rules] injected data rule` 日志便于排查。
> 数据型规则的 CSS id 为 `site-custom-css-<ruleId>`。

`runWebviewCss(styleId, css, tabId)` — 三级回退：

1. `css === ''` → `executeJavaScript` 移除 `#styleId` 节点
2. `w.insertCSS(css)` 可用 → 用返回的 key 记录，可被 `removeInsertedCSS` 撤销（**能绕过 CSP**）
3. 回退 → 注入 `<style id="styleId">` 到 `document.documentElement`

`runWebviewJS(script, tabId)` — 直接 `w.executeJavaScript(script)`。

**去重机制**：两者都以内容签名（`script` / `styleId::css` 的**前 512 字符**）记入 `lastExecutedScripts`，**1200ms 内**重复则跳过。这是**时间窗去重，不是永久去重**——跨 `dom-ready` 的重复注入依赖脚本自身的 `window.__xxx` guard。

**无超时、无重试。**

### 7.5 注入的前置校验

`runWebviewJS` / `runWebviewCss` 都会先检查：

```js
tab 存在 && tab.kind !== 'dashboard' && webviewReadyMap[tid]
```

即：控制台页与本地文本页永远不会被注入。

## 10. 网络与遥测

### 10.1 Axios 封装

`src/http/index.js`：`baseURL = import.meta.env.VITE_APP_BASE_API || ''`，超时 10s，`Content-Type: application/json;charset=UTF-8`。

- **Loading**：延迟 **200ms** 才显示（避免快请求闪烁），引用计数归零才关闭
- **请求拦截器**：若 `localStorage.token` 存在则加 `Authorization: Bearer <token>` —— **全库无任何地方写入该 token**，属死代码
- **响应拦截器**：约定响应体 `{ success, msg, data }`；`success === false` 弹 `msg`；`Network Error` → 网络错误提示；**HTTP 401 静默 reject**（无提示）

导出 `getAsync/postAsync`（返 data）、`get/post/put/del`（返 data）、`upload`（multipart）。

### 10.2 全部远程调用（共 2 个端点）

| 端点 | 调用处 | 参数/体 |
|---|---|---|
| `GET /api/MoYu/CheckVersion` | `App.vue` onMounted、`AboutPage.checkUpdate` | `{ platform: 'win'\|'mac' }` |
| `POST /api/MoYu/ReportDevice` | `useDeviceReport.reportDevice` | `{ deviceId, platform, appVersion, osInfo }` |

基址：开发 `http://localhost:7000`，生产 `https://gateway.benchi.xyz`。

#### 总开关：`backendEnabled`（当前默认 `false`）

两个端点**都**被 [`defaultSettings.backendEnabled`](../MoYu/src/shared/defaultSettings.js) 门禁，默认关闭。此处为**单一开关**而非散落的注释，便于整体启停。

| 调用点 | 门禁位置 |
|---|---|
| `App.vue` onMounted 的 `CheckVersion` | `if (settings.backendEnabled && desktopApi?.checkForUpdate)` |
| `AboutPage.checkUpdate` 的 `CheckVersion` | 函数开头 `if (!settings.backendEnabled)` 提前返回并提示 |
| `useDeviceReport.reportDevice` 的 `ReportDevice` | 函数开头 `if (!isBackendEnabled()) return` |

`useDeviceReport.js` 里的 `isBackendEnabled()` 直接从**共享默认配置**读取，而不是读运行时 `settings`——因为上报可能在 `settings` 从主进程加载完成前被调用（`handlePrivacyAgreed` 可早于 `getSettings()` 返回），读默认值可避免时序漏洞。

**关闭后的重要副作用（正向）**：`App.vue` 的启动检测原本在 `CheckVersion` **请求失败**时也会 `setForceUpdateActive(true)` 并强制跳转更新页（兜底文案是加 QQ 群）。关掉开关后这条路径不再触发，断网用户不会被锁在更新页。

**`window.desktop.checkForUpdate()` 不是网络请求**：它是主进程 IPC（`update:check`），只返回 `{ currentVersion, platform, isDev }`。因此 `AboutPage` 的版本号显示、以及 `useDeviceReport` 拼 payload 用的 `platform`/`appVersion` 都不受影响。

### 10.3 遥测细节（隐私相关）

**双重条件**：`backendEnabled === true` **且** `localStorage['moyu-privacy-consent'] === '1'`。两者是与的关系——即使重新开启后端服务，未明确同意的用户也不会被上报。

**两个调用点**：
- `handlePrivacyAgreed()` — 用户当次点"同意并继续"后立即上报
- `onMounted()` — `if (hasPrivacyConsent) reportDevice()`，每次启动静默上报一次

**上报字段**：

| 字段 | 来源 |
|---|---|
| `deviceId` | 主进程 `userData/.moyu_device_id`，内容为 `randomUUID()`，**明文存盘** |
| `platform` | `'win'` \| `'mac'` |
| `appVersion` | `app.getVersion()` |
| `osInfo` | UA 正则解析：Windows NT 版本映射 / macOS 版本 / **兜底取 UA 前 80 字符** |

**实现与文案的偏差**：`PrivacyConsent.vue` 声称"所有数据均以加密哈希形式匿名上报，无法追溯到具体设备"，但 `deviceId` 是明文持久化 UUID——**同一设备的多次上报可被关联**。且文案提及"崩溃分析"，而代码中崩溃/错误仅写本地日志（`renderer:log`），**无远程上报路径**。

**弹窗行为**：✕ 按钮（`handleDismiss`）**不写任何存储**，只关闭本次；下次启动继续弹。只有"同意并继续"才写标记。

**未上报**：浏览历史、URL、页面标题、阅读内容——这些只在本地 localStorage。

### 11.0 运行命令速查

所有命令在 **`MoYu/`** 下执行。首次需 `npm install`。

| 目标 | 命令 | 界面来源 | preload（`window.desktop`） | 适用 |

| 打包（目录） | `npm run pack` | — | — | 快速本地验证 |
| 打包（安装包） | `npm run dist:win` / `dist:mac` | — | — | 出正式产物 |

**判定依据**（`electron/main.js` 的 `getWindowUrl`）：

```js
const isDev = !app.isPackaged
const isDevServerRun = process.env.npm_lifecycle_event === 'dev'
                     || process.env.npm_lifecycle_event === 'dev:electron'
if (isDev && isDevServerRun) return `http://127.0.0.1:5173/#${hash}`
return `file://${path.join(__dirname, '../dist/index.html')}#${hash}`
```

因此 **`npm start` 不连 dev server**，必须先 `npm run build`，否则加载的是旧产物或白屏。`npm run dev` 用 `concurrently` 并行跑 `dev:web` + `dev:electron`，后者带 `wait-on tcp:5173` 等端口就绪，避免竞态白屏。

**仅网页模式的降级行为**：浏览器中 `window.desktop` 为 `null`（`useAppState.js` 模块加载时取值），所有依赖 IPC 的动作会把提示写进 `statusMessage` 而不抛错。不可用的功能：老板键/托盘/全局快捷键、透明度与置顶、鼠标穿透、防截屏、`<webview>` 多标签、摸鱼统计、本地文件读写。

`dev:electron` 里的 `chcp 65001 >nul` 是 **Windows 专用**（UTF-8 控制台）；macOS/Linux 直接用 `electron .`。

```json
  "nsis": { "oneClick": false, "allowToChangeInstallationDirectory": true, ... }

```

`files` 里包含 `src/**/*` 是有意为之——主进程 `import defaultSettings from '../src/shared/defaultSettings.js'` 需要该文件在 asar 内。

`mac.identity: null` 表示**不做签名**（本地测试用）。

## 12. 数据字典

### 12.1 Tab 对象

```js
{
  id,            // number，generateUniqueTabId() = ++_tabIdCounter（初值 Date.now()）
  title,         // string
  url,           // string
  subtitle,      // string
  kind,          // 'dashboard' | 'page'
  objectUrl,     // string|undefined，blob URL，关闭时 revoke
  pinned,        // boolean|undefined，仅 updateTabMetadata 可写
}
```

初始 tab 固定为 `{ id: 0, title: '工作台', url: 'about:blank', kind: 'dashboard' }`。

### 12.2 最近访问条目

```js
{ title, url, type: 'site' | 'file', time }   // time 由 pushRecentVisit 自动补 ISO 字符串
```

按 `url` 去重（同 URL 先删后 unshift），上限 200。

### 12.3 推荐站点

```js
{ id, name, url, system: boolean }
```

6 个内置 `system: true`：微信读书、番茄小说、Bilibili、抖音、小红书、知乎。持久化时**只存非 system 项**（`persistRecommendedSites`），恢复时重新拼接内置项并去重。

### 12.4 摸鱼会话

```js
{ "YYYY-MM-DD": [ { start: epochMs, end: epochMs }, ... ] }
```

存于 `electron-store` 键 `moyuSessions`。渲染进程额外拿到 `activeStart` 用于实时计时。

### 12.5 localStorage 键总表

| 键 | 内容 | 上限 |

### 13.2 架构层面的注意点

- **webview 无 partition**：所有标签共享 session，cookie/localStorage 互通，无法做多账号隔离。
- **webview 常驻内存**：`v-show` 而非 `v-if`，标签数增长时内存线性上升，且每个 guest `WebContents` 都会注册监听器（故 `win.webContents.setMaxListeners(100)`）。
- **注入去重是时间窗**：1200ms 内去重，跨 dom-ready 靠脚本自 guard。新写的规则必须自己加 `window.__xxx` guard。
- **`settingsRules` provider 是死路径**：已实现完整 CRUD 与匹配，但 `MainPage` 从不读 `combined.settings`。
- **`toolbarRules` 只取第一条**：`toolbar[0]`，多条匹配时后续被忽略。
- **`asar: true` + `src/**/*` 打包**：主进程 `import '../src/shared/defaultSettings.js'` 依赖源码进包，重构目录结构时需同步 `build.files`。
- **`sandbox: false`**：preload 需要它才能注入，但降低了渲染进程隔离等级。
